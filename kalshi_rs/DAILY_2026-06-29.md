# Daily — 2026-06-29 — Kalshi f6 live: почему теряем и что починили

## TL;DR
Разобрались, **почему live-бот ($5 реальных) в минусе −$65, хотя пейпер на дашборде +$4191**. Главный вывод:
edge **не сдох** — он тонкий (net +2.6%/сделку только при WR ≥ ~74%), а live словил near-breakeven
участок (WR 71%) + структурную комиссию Kalshi (~2%) + транзиентные потери сделок (мои рестарты при
деплоях + временный max_entry-кэп). Исполнение (слиппедж) при этом **≈ ноль** — подтверждено P0-телеметрией.
Зашипили: P0-телеметрию (слайсы 1-5), keep-warm + HTTP/2 для ордерного соединения, env-override `MAX_ENTRY`,
и P0b — фикс защёлки окна (непролив больше не сжигает окно). Поставили tripwire: неделя данных, WR≥74% —
работаем, <73% — стоп.

## Что и зачем сделано (хронологически)

### 1. P0 — телеметрия исполнения (слайсы 1-5, задеплоено ~28.06 15:20 UTC)
Цель: измерить, откуда берётся разрыв live vs paper по цене входа, т.к. раньше летели вслепую.
- `ledger.rs`: типизированная запись `LiveTriggerRecord` + enum `Outcome`
  (filled|partial|nofill|skip_daily_cap|skip_loss_stop|skip_band|order_error|rejected), поля
  `signal_entry/exec_entry/eff/first_limit_price/requote/remaining_count/fill/fee/latency_ms`.
- `main.rs`: `place_live` теперь возвращает `Outcome` и пишет запись на КАЖДОМ исходе, включая
  непроливы и скипы (раньше — тишина). Лоадер дашборда считает триггером только filled/partial
  (старые записи без `outcome` = filled, для обратной совместимости).
- Чистые хелперы: `classify_outcome`, `decompose_gap` (drift = exec−signal, walk = eff−exec),
  `is_dashboard_trigger`. Полное юнит-покрытие.

### 2. Латентность ордера: keep-warm + HTTP/2
Замер с EU-бокса: ping до CloudFront-точки Kalshi = **4.8мс** (сеть НЕ проблема), но холодный
ордер платит TCP+TLS-хендшейк (**~280мс**), тёплый — **~105мс**. Ордера идут раз в ~15 мин (дольше
idle-таймаута пула reqwest) → каждый холодный.
- `OrderClient`: `pool_idle_timeout(None)` + `tcp_keepalive(30s)`; фоновый пинг `GET /portfolio/balance`
  каждые 30с (`ORDER_WARM_SECS`).
- Включили фичу `http2` + `http2_keep_alive_interval(15s)/timeout(10s)/while_idle(true)` —
  reqwest был собран без http2 (HTTP/1.1), и пул h1 не переиспользовал тёплое соединение надёжно.
- **Итог по латентности:** частично. Тёплые филлы ~105-128мс (пол), но ~46% всё ещё холодные ~280-477мс.
  Полностью лечится только колокацией в us-east — а её нельзя (binance.com заблокирован в US, сигнал
  считается на нём; максимум — сплит «сигнал ЕС → исполнение-релей us-east», сложно). **Слиппедж по
  телеметрии ≈ 0**, так что латентность оказалась НЕ главным источником убытка.

### 3. Эксперимент max_entry 0.85 (выкатили и ОТКАТИЛИ)
Свип по истории (idealised) показал, что дорогой хвост 0.85-0.92 даёт мало EV/сделку → поставили
`MAX_ENTRY=0.85` (через новый env-override `resolve_max_entry`). **БЭКФАЙРНУЛО:** за ночь дорогие
входы >0.85, которые бот стал пропускать, дали **WR 91%** и были прибыльны, а дешёвые ≤0.85, что бот
брал, — **WR 61%**. Классическая переподгонка (in-sample). **Откатили обратно на 0.92.** Урок: backtest
идеализирован, относительные оптимумы не переносятся на живой режим вслепую.

### 4. Риск-параметры
`DAILY_LOSS_STOP` 50→100 (по просьбе — дать запас под возможный разворот, не стопиться рано).

## Корневая причина убытка (железная сверка)
Сджойнили live-леджер с пейпер-движком трейд-в-трейд:
- **225 совпадающих сделок (market+side): 100% одинаковый исход, WR live 71% = пейпер 71%,
  разрыв входа +0.74¢.** → live делает РОВНО то же, что пейпер. Бага исполнения НЕТ.
- **Разрыв входа (eff − signal_entry) ≈ 0** (средн. −0.24¢; drift +0.46¢ и walk −0.70¢ гасятся),
  утечка исполнения −$0.80 на 58 филлов. **Слиппедж не виноват.**
- **Раскладка −$65.66:** направление без комиссии −$41.34 (WR 70% ниже breakeven ~72%) +
  **комиссия Kalshi −$24.32** (per-contract `ceil(0.07·C·P·(1−P))`, ~$0.11/сделку ≈ 2.2% ставки;
  подтверждено офиц. fee schedule — крипто на общих 0.07, наш код верен).
- **Зелёная линия на дашборде = реальный пейпер-движок** (НЕ бэктест), при $100 и БЕЗ комиссий.
  Её +$4191 заработаны в основном **22-25 июня — ДО запуска live (26-го)**. Над окном live (26-29)
  пейпер был ~в нуле (+$743 gross-$100-no-fee = +$3.90 net@$5 с комиссией). Live встал на деньги
  на вершине, в плоский участок.
- **Пропущенные сделки:** live взял 226 из ~312 пейпер-сделок окна. Но из 86 пропусков по логам:
  **17 непроливов** (защёлка), 11 дневной-кэп, 8 re-quote, 7 mirror-хиккапов, остальное — **мои
  ~10 рестартов при деплоях** + откатанный max_entry-кэп. То есть почти всё транзиентное, не лик.

## P0b — фикс защёлки окна (слайс 6, эта правка)
Баг: `fired_window` ставился ДО `place_live().await` → любой непролив навсегда сжигал единственную
сделку окна (17 непроливов = потерянные сделки).
- Окно латчится только на неретраябельном исходе (filled/partial, или осознанный skip_*); непролив/
  order_error/rejected — **ретрай внутри окна**, ограниченный `RETRY_MAX_ATTEMPTS` (деф. 2) +
  `RETRY_COOLDOWN_SECS` (деф. 3.0). Скипы латчат сразу (без спама).
- Инварианты: максимум одна позиция на окно (филл латчит), `trades_today` растёт только на филл,
  `N=1/C=0` = старое поведение (one-shot). Хелперы `latch_decision/counts_as_attempt/retry_gate` —
  чистые, юнит-протестированы (симуляция оконного автомата). 33 теста зелёные.

## Текущее состояние
- Live: реальный $5, `max_entry=0.92`, `DAILY_LOSS_STOP=100`, http2 keep-warm, P0-телеметрия.
  P0b — на ветке, деплой по подтверждению.
- total real PnL ≈ −$66. Edge тонкий: net +2.6%/сделку при WR≥74%, минус при <73%.

## Tripwire (решение по данным, не по настроению)
Неделя живых данных. **WR ≥ 74% → стратегия жива, работаем. WR < 73% стабильно → edge сдулся, стоп.**
Чинимое мы выжали (защёлка, исполнение); комиссия ~2% структурна (мейкер не подходит — momentum, налив
только на развороте). Дальше решает только сам винрейт.

## Изоляция на сабаккаунте (вечер 29.06)
Проверили Kalshi-сабаккаунты: `GET /trade-api/v2/portfolio/subaccounts/balances` показал основной (0)
≈$16.8k и пустой №1 ($0, создан ~26.06). Перевели на №1 ровно **$200**
(`POST /trade-api/v2/portfolio/subaccounts/transfer`, поля `from_subaccount/to_subaccount/amount_cents`,
2 перевода, оба HTTP 200). Затем добавили в ордер поле **`subaccount`** (V2Order, env `SUBACCOUNT`,
эндпоинт `/portfolio/events/orders` принимает его; подпись не меняется — тело не подписывается),
выставили `SUBACCOUNT=1`, пересобрали и перезапустили. **Верифицировано вживую:** ордер
`LIVE FILLED YES 8x @ 0.58` списался с №1 ($200→$195.22), счёт 0 не тронут новыми сделками. Теперь
live изолирован на $200 в сабаккаунте №1. ВНИМАНИЕ: loss-stop $100/сутки на $200 = 50%/день — стоит
ужесточить (напр. $30) под изолированный капитал; пока оставлен $100 по решению пользователя.
