   без ключа), резолв PnL по реальному расчёту Kalshi (индекс BRTI). JSONL-леджер would-be ордеров.
2. **Деплой**: systemd-сервис `kalshi-shadow` на US-сервере (Buffalo 23.95.217.78) — live shadow, на
   триггере пишет «пустой» ордер. Автозапуск + restart=always.
3. **Прод-разведка** (GCP `trading-bot-5sec`, EU): нашёл Kalshi-креды (Key ID + RSA) и данные пейпера
   (`paper_compare_kalshi_15m/live_data.db`, сессия `f6_wait270`). Сверил мою RSA-PSS подпись и формулы
   (книга `1−opp_bid`, entry `max(yes_ask,no_ask)`, резолв) — **идентичны прод-коду** (`ll_feed.py`).
4. **Дашборд сравнения** (http://23.95.217.78:8890): 3 фида side-by-side (paper / US-Binance.US /
   COM-Binance.com) + проценты совпадения + **TradingView Lightweight Charts** кумулятивного PnL.
   Прод-крон каждую минуту пушит f6-трейды пейпера; EU-инстанс пушит COM-триггеры. Cutoff персистентный.

## Ключевые находки / фиксы
1. **Баг τ-нормализации (главный).** Живой Kalshi-15m пейпер делит τ на длину окна (`/60/WINDOW_MINUTES`
   → τ∈[0,1]); спек (под Polymarket) говорил «сырые минуты». Я брал τ=10.5 вместо 0.7 → p занижена в ~15× →
   бот входил поздно (7–15 мин вместо 4.5) → на развороте → обратная сторона. **Пофикшено** → US сразу 100% (2/2).
2. **Binance.US мёртв.** 123 BTC/сутки vs Binance.com 34 882 (×283 тоньше) → редкие/застойные цены →
   кривой Δ → 25% окон обратная сторона. **Отброшен.**
3. **Binance.com (COM) = эталон.** 97.4% по стороне, entry-diff медиана 1 цент (мои entry даже свежее:
   поллинг 1с vs пейпер 3с), момент входа в среднем 0.7с (мой чуть раньше). Логика верна.
